# Text-to-SQL Fine-tuning — QLoRA на Qwen2.5-Coder-7B

Дообучение открытой LLM для перевода вопросов на естественном языке в
SQL-запросы. Честный, полностью задокументированный путь от zero-shot
baseline до результата, превосходящего сопоставимую опубликованную
работу — включая найденные и исправленные технические ошибки, а не
только финальную метрику.

## Результат

| Этап | Execution Accuracy |
|---|---|
| Zero-shot baseline (без дообучения) | 69.5% |
| Наивное SFT-дообучение (до исправления багов) | 63.0–67.0% (хуже baseline) |
| SFT после исправления 3 технических багов | 70.0–73.5% |
| **Финал** (SFT + 3 inference-time техники, эпох подобрано перебором) | **78.5%** |

**+9.0 п.п. над собственным baseline**, превосходит сопоставимую
опубликованную работу (Llama 3 8B, тот же датасет, похожий QLoRA-подход,
77.2% EX) на 1.3 п.п.

## Почему это не просто «запустил туториал»

Путь к финальному результату включал систематическое нахождение и
исправление **7+ реальных технических ошибок** — не косметических, а
существенно влиявших на результат:

- Loss считался по всему промпту (включая схему БД), не только по
  целевому SQL — модель тратила градиенты на «копирование» контекста
- Отсутствие LR-расписания (warmup + cosine decay)
- Сброс состояния оптимизатора при возобновлении обучения после сбоя
- Дважды — один и тот же класс бага в постобработке (коррекция кавычек
  ломала строковые литералы вроде `'USA'`, приняв их за галлюцинированные
  имена колонок)

Подробный разбор каждой находки — в [`technical_lessons_learned.md`](./technical_lessons_learned.md).

## Подход

1. **Собственный перебор гиперпараметров**, не копирование чужих
   значений — число эпох обучения (1–4) и LoRA rank (16 vs 32)
   протестированы самостоятельно; оптимум для этой модели/датасета
   оказался **не** таким, как в референсной работе
2. **Диагностика перед починкой** — реальная классификация ошибок по
   типам на 200 примерах, прежде чем писать код исправления
3. **Пять inference-time техник** проверены по отдельности и в
   комбинациях: постобработка сгенерированного SQL, точечный поиск
   значений в БД, общие примеры строк в схеме, few-shot, продвинутая
   самокоррекция — не все оказались полезны, отрицательные результаты
   задокументированы наравне с положительными
4. **Регрессионный анализ после каждого изменения** — не только
   агрегированная метрика, сравнение по конкретным примерам
