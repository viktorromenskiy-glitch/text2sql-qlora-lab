# Text-to-SQL Fine-tuning — QLoRA на Qwen2.5-Coder-7B

Донавчання відкритої LLM для перекладу питань природною мовою в
SQL-запити. Чесний, повністю задокументований шлях від zero-shot
baseline до результату, що перевершує співставну опубліковану роботу —
включно зі знайденими та виправленими технічними помилками, а не лише
фінальною метрикою.

*English version: [README.en.md](./README.en.md) · Русская версия: [README.md](./README.md)*

## Результат

| Етап | Execution Accuracy |
|---|---|
| Zero-shot baseline (без донавчання) | 69.5% |
| Наївне SFT-донавчання (до виправлення багів) | 63.0–67.0% (гірше за baseline) |
| SFT після виправлення 3 технічних багів | 70.0–73.5% |
| **Фінал** (SFT + 3 inference-time техніки, епохи підібрані перебором) | **78.5%** |

**+9.0 в.п. над власним baseline**, перевершує співставну опубліковану
роботу (Llama 3 8B, той самий датасет, схожий QLoRA-підхід, 77.2% EX)
на 1.3 в.п.

## Чому це не просто «запустив туторіал»

Шлях до фінального результату включав систематичне знаходження та
виправлення **7+ реальних технічних помилок** — не косметичних, а
таких, що суттєво впливали на результат:

- Loss рахувався по всьому промпту (включно зі схемою БД), не лише за
  цільовим SQL — модель витрачала градієнти на «копіювання» контексту
- Відсутність LR-розкладу (warmup + cosine decay)
- Скидання стану оптимізатора при відновленні навчання після збою
- Двічі — один і той самий клас бага в постобробці (корекція лапок
  ламала рядкові літерали на кшталт `'USA'`, прийнявши їх за
  галюциновані імена колонок)

Детальний розбір кожної знахідки — у [`technical_lessons_learned.md`](./technical_lessons_learned.md).

## Підхід

1. **Власний перебір гіперпараметрів**, не копіювання чужих значень —
   кількість епох навчання (1–4) та LoRA rank (16 vs 32) протестовані
   самостійно; оптимум для цієї моделі/датасету виявився не таким, як
   у референсній роботі
2. **Діагностика перед виправленням** — реальна класифікація помилок за
   типами на 200 прикладах, перш ніж писати код виправлення
3. **П'ять inference-time технік** перевірені окремо та в комбінаціях:
   постобробка згенерованого SQL, точковий пошук значень у БД, загальні
   приклади рядків у схемі, few-shot, просунута самокорекція — не всі
   виявились корисними, негативні результати задокументовані нарівні
   з позитивними
4. **Регресійний аналіз після кожної зміни** — не лише агрегована
   метрика, порівняння за конкретними прикладами
