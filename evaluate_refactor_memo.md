# Пояснительная записка — рефакторинг evaluate.py (Spider-часть)

## Что сделано сейчас

Объединил `evaluate_baseline.py` и `evaluate_lora.py` в единый
`scripts/evaluate.py` + `configs/eval_config.yaml`, по исходной
спецификации (`module_specifications.md`). Только для **Spider dev** —
BIRD-SQL сознательно не добавлен, см. ниже почему.

**Что реально проверено** (без GPU, локально):
- `eval_config.yaml` — валидный YAML, все нужные поля
- Логика сравнения baseline vs LoRA — на реальных вчерашних числах
- Аргументы командной строки (`--model baseline/lora/both`) —
  корректная обработка выбора и значения по умолчанию

**Что НЕ проверено** (требует GPU, будет проверено при первом реальном
запуске): сама загрузка моделей, генерация, полный цикл `run_eval()`.
Как и весь предыдущий код в этом проекте — считать непроверенным до
первого реального прогона в Colab.

## Почему решение было именно «сейчас, но только Spider»

**Довод за рефакторинг сейчас, а не откладывание**: расхождение между
спецификацией и кодом дешевле исправить, пока это два файла, а не три
(если бы сначала появился `evaluate_bird.py`, объединять пришлось бы
уже три источника логики вместо двух).

**Довод за ограничение только Spider, не «сразу всё»**: BIRD-SQL ещё не
скачан (`data/README.md` — скачивание не автоматизировано), и у
`load_bird()` в `src/dataset.py` есть известный, явно
задокументированный пробел — схема базы данных не прикрепляется к
примерам (в отличие от `load_spider()`). Писать код для BIRD прямо
сейчас означало бы писать и проверять его вслепую, без возможности
реального прогона — тот же риск, которого хотели избежать, откладывая
рефакторинг целиком.

## Что осталось сделать позже, к Вехе 3 — конкретно

1. **Скачать BIRD-SQL** — ручной шаг, см. `data/README.md`
2. **Закрыть пробел в `load_bird()`** — прикрепить схему базы данных к
   каждому примеру (аналогично тому, как `load_spider()` уже делает
   через `tables.json`) — нужно сначала посмотреть на реальную
   структуру скачанного BIRD-SQL, догадываться заранее не стоит
3. **Расширить `eval_config.yaml`** — добавить `datasets.bird_dev`
4. **Расширить `evaluate.py`** — добавить обработку BIRD как ещё одного
   датасета в `run_eval()`/`main()`, по той же схеме, что уже есть для
   Spider — это должно быть небольшим, добавочным изменением к уже
   работающему файлу, не переписыванием с нуля

## Что заменяет что — для ясности при загрузке на GitHub

- `evaluate.py` заменяет **и** `evaluate_baseline.py`, **и**
  `evaluate_lora.py` — можно удалить оба старых файла из `scripts/`
  после того, как `evaluate.py` пройдёт реальную проверку в Colab (не
  раньше — не удалять рабочий, проверенный код до того, как новый
  подтверждён)
- `eval_config.yaml` — новый файл, кладётся в `configs/`, рядом с
  `train_config.yaml`
